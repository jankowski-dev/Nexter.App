# Decision Log

Format: date — decision — reason.

## 2026-11-02

- **Single-user application.** One owner, closed registration, `user_id` in future tables. Simpler auth and data model.
- **USD as base accounting currency.** BYN is deferred and will be a reporting/display currency.
- **Non-custodial swaps only.** Private keys stay in Tangem; the server never signs.
- **BSC first, Ethereum second.** Lower fees and faster iteration on BSC.
- **Modular monolith.** NestJS + React SPA + Postgres + worker; no microservices.
- **Postgres + Drizzle.** SQL control, typed schema, forward-only migrations.
- **pg-boss instead of Redis.** Fewer services, transactional jobs on Postgres.
- **Ledger + postings + FIFO lots.** Required for auditable accounting, transfers, fees, and partial exits.
- **FIFO is global per asset for MVP.** Simpler than per-account lots; can be extended later.
- **Stablecoins are cash equivalents.** No FIFO lots for USDT/USDC; depeg flag stays.
- **Gas is added to cost basis by default.** Configurable in settings; never double-count execution cost.
- **Notion is the historical source for MVP-1.** On-chain reconciliation is deferred to MVP-3.
- **No wallet access in MVP-1.** The owner explicitly deferred wallet connection.
- **Step-up TOTP threshold $500.** Extra protection for larger swaps; configurable.
- **Cloudflare Access optional.** App auth remains mandatory.
- **RPO 1 hour / RTO 4 hours.** PITR + encrypted dumps to R2.
- **Sentry SaaS with scrubbing.** No PII or wallet addresses in events.

- **PostgreSQL readiness is tested in CI.** The API e2e suite runs a DB-backed `/ready` test when `DATABASE_URL` is set and skips it locally.
- **Sentry scrubbing includes user context and arrays.** `event.user` is removed and nested arrays are recursively scrubbed.
- **Phase 1 accepted with operational follow-ups.** Independent review round 4 returned PASS WITH CHANGES: no Critical/High findings. Remaining work is Railway staging, actual proxy CIDRs, real CI/Docker execution, broader DB auth tests, and version/digest hardening.
- **Custom auth module instead of a framework.** Argon2id, TOTP, recovery codes, server-side sessions, and explicit guards keep the security model auditable and avoid a large auth dependency.
- **CSRF uses a double-submit cookie plus a session hash.** The SPA reads `nexter_csrf`; the API requires `X-CSRF-Token`, compares it to the cookie, and verifies its hash against the session.
- **TOTP secrets are encrypted with AES-256-GCM.** `AUTH_ENCRYPTION_KEY` is a 32-byte base64/hex secret and is required in production/staging.
- **Recovery codes are one-time and hashed.** Password reset consumes a code, revokes all sessions, and issues ten new codes.
- **Auth rate limits are database-backed.** `rate_limits` provides per-IP/per-user lockout without adding Redis.
- **Pending-2FA sessions are isolated by a global guard.** Only explicitly allowed auth endpoints can be used before TOTP verification.
- **No email is sent.** Setup, login, TOTP, recovery, and password reset are fully self-hosted.
- **TOTP lockout is per-user and enforced before verification.** The counter is keyed `2fa:<user_id>`, checked before decrypting a code, and not reset by a password-only login. A valid code cannot bypass an active block.
- **First-run setup is single-owner at the database level.** `users_singleton_unique` plus an advisory-lock transaction prevents two owners under concurrency; the loser receives `409`.
- **Password change rotates the current session.** The old session and all other sessions are revoked, and a new verified session is issued. This resolves the contract/spec conflict in favor of rotation.
- **Recovery-code consumption is atomic.** Verification and reset use row locks, so a code cannot be consumed twice under concurrency.
- **Credential/session mutations and their audit rows share a transaction.** If the audit insert fails, the mutation rolls back; failed attempts remain best-effort audit writes.
- **Session TTL is absolute 30 days.** Sliding renewal is deferred; see ADR 0005. Activity updates `last_seen_at`, not `expires_at`.
- **`AUTH_ENCRYPTION_KEY` is validated at startup and before setup.** A malformed key cannot create an owner that then cannot complete TOTP setup.
- **Login throttling is per IP+email pair and per IP.** Unknown emails still pay an Argon2 dummy verification; login counters reset only after 2FA or a password reset/change. A global per-email lockout is intentionally avoided.
- **Break-glass recovery is an offline runbook.** The setup token is not a recovery path; see `docs/runbooks/auth-recovery.md`.
- **Phase 2 review fixes are covered by tests.** API auth e2e now covers setup races, lockout, recovery/reset, session revocation, CSRF, audit, and password-change rotation; Playwright covers the browser auth flow.
- **Login session creation and audit are transactional.** A failed audit write rolls back the login session; this closes the last rule-6 gap.
- **Login throttling uses per-IP+email keys.** A global per-email lockout was rejected because it would let an unauthenticated attacker deny login to the single owner.
- **Password reset/change clear auth lockouts.** Recovery after an attacker-triggered 2FA lockout is not blocked; the break-glass runbook also clears `rate_limits`.
- **Destructive auth tests require `NEXTER_TEST_DB=1`.** CI uses a disposable PostgreSQL service; local runs must use a dedicated test database.
- **Phase 2 accepted.** Three independent reviews: FAIL → PASS WITH CHANGES → PASS WITH CHANGES; all Critical/High and actionable Medium findings fixed. Final green CI: `6d09b82`. Next phase: Phase 3 — Accounting core.
- **Phase 3 uses an append-only ledger with per-chain assets.** `transactions` + signed `postings` are the source of truth; balances and P&L are derived. Assets are unique per `(chain, symbol)` so BSC USDC and Ethereum USDC can have different decimals.
- **Default accounts are bootstrapped idempotently.** Every owner gets system accounts and `Tangem BSC`/`Tangem Ethereum` wallets; account rows are audited.
- **FIFO is global per asset.** Lots are not per account; transfers do not change lots. Stablecoins are cash equivalents and do not create lots.
- **Manual prices only in Phase 3.** No external price provider is added. Missing prices are represented as `null` and listed in `missingPrices`, never invented.
- **Income is separate from disposal P&L.** `incomeUsd` is included in total P&L; realized disposal P&L remains `proceeds − cost basis − selling fees`.
- **MVP manual buys/sells require a cash-equivalent quote/proceeds asset.** Token-to-token swaps remain supported; broader quote assets are a later extension.
- **Manual transactions are audited in the same transaction as the ledger writes.** Price changes are audited too; account bootstrap writes audit rows.
- **Manual writes are serialized per user.** A PostgreSQL advisory transaction lock makes the balance re-check safe under concurrent cash spends.
- **Withdrawals of non-cash assets realize disposal P&L.** Cash withdrawals remain capital flows; this keeps `equity − netDeposits = totalPnl`.
- **Positive adjustments and non-capitalized fees are explicit P&L components.** `adjustmentsUsd` and `feesUsd` are reported separately; fee amounts already capitalized or deducted from realized P&L are not counted twice. Adjustment reasons are persisted and audited.
- **Manual POSTs accept an `Idempotency-Key`.** Transaction `source_id` plus the unique user/source index makes retries replay the original transaction.
- **Asset decimals and wallet chain consistency are validated.** Amounts may not exceed `assets.decimals`; a wallet may only hold assets from its chain.
- **Cash-equivalent USD is derived and enforced.** Cash equivalents are valued at $1 in Phase 3; explicit USD for a cash leg must equal the token amount. Manual cash prices are ignored until a depeg flag exists.
- **Fee USD must be positive and consistent with cash fees.** A zero fee USD is rejected; a cash fee USD must equal the cash fee amount.

## Phase 4 — Notion import

- **Phase 4 imports the current 431-order Notion export, not only the 429-order audit snapshot.** The 429 baseline remains the control; orders `465`/`466` (opened after the snapshot) and closed orders `450`/`463` (still active in the snapshot) are the known adjustments.
- **Control reconciliation reconstructs the 429 baseline explicitly.** Preview excludes the two post-snapshot orders and treats the two later-closed orders as active, then compares counts, transaction totals, cash, and active cost to the Phase 3 control within ±$0.01. A failed applicable baseline blocks commit. Price-dependent snapshot metrics (active value, equity, unrealized/total P&L) were calculated at audit-time prices and are reported separately, not gated.
- **Raw Notion exports are staged, not committed.** `imports`/`import_rows` keep normalized rows and source hashes; the repository never stores the export. The import preview uses `application/x-notion-import+json` with a route-specific 10 MiB limit and a lossless JSON parser that keeps numeric literals as strings; other routes keep 1 MiB.
- **Closed Notion orders use per-order lots.** Each order gets a trade group and a lot; a closed order consumes its own lot, preserving historical Notion cost basis. Imported active lots remain in the normal global FIFO pool: a later manual sell may consume them, and a later Notion close for the same partially consumed lot is rejected as `IMPORT_CONFLICT` instead of double-counting the disposal.
- **Notion close dates are date-only for some rows.** Those values are normalized to `23:59:59.999Z` on that date so the sell follows the buy on the same day.
- **USDT prices from Notion are ignored.** USDT is a cash equivalent valued at $1; non-cash `Курс [1]` values are stored as `source=notion` prices with `import_id`.
- **Imports are idempotent at row level.** Deterministic `notion:order:<id>:buy`, `:sell`, and `notion:transaction:<pageId>` source ids prevent duplicates. Re-exports skip existing rows and can add a sell to an already imported active order. Commit re-runs detection under the user lock, so a preview → rollback → commit sequence re-opens skipped rows instead of silently committing an empty import.
- **Import and manual writes share one advisory lock.** This prevents imports from racing manual ledger writes and negative-balance checks.
- **Rollback is a narrow import-admin exception.** It is allowed only for the newest committed import with no later non-import activity; it removes the import's transactions, lots, groups, and prices, restores lots for active→closed updates, and restores previous group status/closedAt from `import_rows.metadata` for status-only and `for_sale`/`reserve` updates. Ordinary ledger mutations remain append-only.
- **The import reconciliation endpoint is read-only.** `GET /api/v1/imports/:id/reconciliation` returns the stored control, current deltas, and valuation.
- **Source watchlist theses/tags are deferred to Phase 5.** Phase 4 imports assets and keeps descriptions in staging; the watchlist table/UI is not part of this phase.
- **Import commit checks final wallet balances only.** The Notion journal has buys before the first recorded deposit, so chronological non-negativity would require inventing an opening balance.
- **Phase 4 UI is limited to `/import`.** Upload, preview, control reconciliation, commit/rollback, history, and a compact post-commit accounting summary. Full dashboard/portfolio/trades UI remains Phase 5.
- **Phase 4 accepted.** Three independent reviews (FAIL → PASS WITH CHANGES → PASS), owner sign-off on the documented scope deviations, and the production 431-row import applied on 2026-11-03. Merge commit `12bfbb0`; main CI passed. Next phase: Phase 5 — MVP-1 UI.

## Phase 5 — MVP-1 UI

The equity curve is explicitly valued at current prices because historical prices are unavailable; true historical valuation needs snapshots.
- **Settings remain narrow in MVP-1.** USD and FIFO are fixed; timezone and `includeGasInCostBasis` are editable and audited. Account management is read-only for now.
- **Audit log has a read API.** The owner sees their entries and system entries; filters and cursor pagination are supported.

- **Watchlist prices are not invented.** 24h change is `null` unless the latest price is less than 24h old and an older price exists. Backfill is marked by audit, runs with `onConflictDoNothing`, and archived entries can be restored.
- **Manual-entry idempotency keys are stable per dialog attempt.** The key is generated when the dialog opens, reused on retries, and reset after success. Trade-group sell accepts the same header.
- **The equity curve is capped to the most recent 36 months** and ends at the current month; older history is folded into the first balance rather than dropping recent months.
- **Cash asset detail is available.** USDT/USDC positions are returned at $1 for the asset detail page; non-cash asset detail loads all trade groups, not just the first 50.

- **Monthly P&L uses the configured IANA timezone.** UI date labels use the browser timezone; this distinction is shown in settings.

- **CSV protection preserves numeric cells.** Only formula-like text is prefixed with `'`; negative decimal values remain numeric in spreadsheets.
- **Microsecond timestamps are paged at millisecond precision.** Audit and watchlist cursors use `date_trunc('milliseconds', ...)` for ordering and predicates, so rows sharing the cursor's millisecond are not skipped. Settings creation is audited as `settings.created`; monthly P&L falls back to `Europe/Minsk`.

## Phase 8 — Swap execution

- **Execution is split into slices.** ADR 0010 covers WalletConnect/Tangem, exact approvals, step-up TOTP, API tracking, and confirmed-swap accounting. The first slice adds step-up TOTP, exact approval build/submission, and order submission state; it does not sign, track, or write accounting yet.
- **Step-up is session-bound and fails closed.** `sessions.step_up_until` is set by a TOTP verification for five minutes and required for build/approval build/ready/signing when the stored input USD value exceeds `SWAP_STEP_UP_THRESHOLD_USD` (default $500). Missing/invalid USD requires step-up; quotes reject a missing provider `amountInUsd`. Failures use the existing 2FA throttle and are audited.
- **Approvals are exact.** The server emits `approve(router, exactAmount)` only, validates the router allowlist and simulation, and never emits unlimited approvals.
- **Submission is idempotent-by-state (superseded by the execution slice).** `POST /swap/orders/:id/submitted` accepts `BUILT`, `READY`, `AWAITING_SIGNATURE`, and `EXPIRED` and records a hash/event/audit as a recovery action; it does not require step-up or re-check allowlists because the wallet has already signed, and tracking verifies the tx. Tx hashes are unique; tracking verifies on-chain. Deadline is persisted on build. Approvals are exact, unique while active, and require the router/wallet allowlists and a live deadline.
- **WalletConnect connection UI.** `/swap` initializes WalletConnect v2 with the public `WALLETCONNECT_PROJECT_ID` returned by `GET /swap/config`, requests BSC 56, displays the connected address/chain, and supports disconnect/switch-to-BSC. Signing is enabled after live acceptance; `SWAP_EXECUTION_ENABLED` and the kill switch remain rollback controls. No private key or seed phrase reaches the server.
- **Zero-allowance ERC-20 builds are handled (superseded).** Build now enters `APPROVAL_REQUIRED`; `ready` re-checks allowance/simulation; submit accepts `READY`/`BUILT`/`AWAITING_SIGNATURE`.
- **WalletConnect CSP origins are explicit.** The API `Content-Security-Policy` allows the documented Reown/WalletConnect `connect-src` and `frame-src` origins (relay, RPC, Web3Modal API, Pulse, verifier) instead of broadening to any https/wss host. Scripts stay `'self'`; the rate-limit response uses the same serialized policy so it cannot drift.
- **Dependency override for the WalletConnect tree.** `zod@<4.6.6` is overridden to 4.6.7 because nested WalletConnect/AppKit dependencies pulled a vulnerable zod 3.x; CI dependency audit must stay clean.

## Phase 8 — calldata verification

- **Correct Kyber selectors.** `swap` is `0xe21fd0e9`; `swapGeneric` is `0x59e50fed`. The earlier allowlist value `0x59e50fed` alone would reject normal Kyber aggregator builds. Both are supported and both must be allowlisted.
- **Router-level decode is mandatory before BUILT.** The server decodes the Kyber execution tuple and verifies source/destination tokens, recipient, input amount, minimum output, executor, approve target, source receivers, fees, permit and partial-fill flags. The executor allowlist defaults to the BSC AggregationExecutorProxy and can be overridden with `SWAP_EXECUTOR_ALLOWLIST`.
- **Deadline policy.** Simple-mode calldata is rejected because `firstPools`/`destTokenFeeData` cannot be validated without a pool allowlist or recursive decode. Normal aggregator calldata has no router-level deadline because the deadline lives in nested executor/DEX calls; the server-enforced order deadline is authoritative for new signing; an already-signed hash can still be recorded after it. Full recursive DEX-call decoding is out of scope.

## Phase 8 — tracking and accounting

- **Tracking runs in the API process.** `SwapTrackingService` polls submitted/confirmed orders, verifies `eth_getTransactionByHash` against sender/router/calldata/value, tracks receipts and confirmations, and records replaced/dropped/failed states. Status updates are conditional and accounting is idempotent via the ledger's per-user advisory lock and `source=kyberswap`/`sourceId=tx hash`. The worker remains reserved for future decoupling.
- **Tracking survives a feature disable.** The poller starts whenever either `BSC_RPC_URL` or `ETHEREUM_RPC_URL` is configured (outside tests), independent of `SWAP_ENABLED`; disabling new swaps must not strand submitted/confirmed orders.
- **Cash-equivalent USD comes from the actual amount.** For USDC/USDT-like legs the tracker omits quote-derived USD and lets the ledger derive it from `executed_amount_*`; non-cash legs scale the quote USD by actual amounts. This avoids rounding mismatches.
- **Accounting retries are persistent.** Confirmed unaccounted orders are retried with a 60-second backoff after failures; there is no 24-hour cutoff. Failures are recorded in order errors/events and audited.
- **Accounting reuses `LedgerService`.** A confirmed swap creates one trade/swap transaction with postings, FIFO consumption, an output lot, gas postings, and a trade group. Actual spent/return amounts are decoded from the router `Swapped` event and stored as `executed_amount_in`/`executed_amount_out`; USD values are scaled from the quote by the actual amounts. Gas wei is actual; gas USD is derived from the quote's gas estimate/price ratio. Accounting requires the input token and native gas balance (BNB/ETH) to exist in the ledger; negative balances fail closed and are retried after reconciliation.
- **Reorg policy.** Receipt and confirmation count are rechecked before accounting; a reorged transaction returns to `PENDING` and a reverted receipt becomes `FAILED`. Post-accounting reorg compensation is an append-only manual correction; `SWAP_CONFIRMATIONS` (default 15) bounds the risk. Automated compensation is a Phase 9 prerequisite.
- **Replacement speed-ups are adopted.** A same-nonce replacement that matches sender/router/calldata/value is adopted and tracked under the new hash; a found-but-mismatched replacement is `REPLACED`. If no replacement is found, the order stays active with a tracking anomaly instead of being terminally dropped.
- **Transaction source.** `kyberswap` is added to the transaction source contract enum; the swap order links to the created transaction and trade group.

## Phase 8 — execution UI and allowance gate

- **Build no longer fails on a first-time ERC-20 approval.** Insufficient allowance produces `APPROVAL_REQUIRED` with stored calldata; `POST /swap/orders/:id/ready` re-checks balance/allowance/simulation and moves the order to `READY`. Submit accepts `READY` or `BUILT`.
- **Signing is gated.** `SWAP_EXECUTION_ENABLED` defaults to false and is exposed as `executionEnabled`; the UI allows build/approval preparation but hides WalletConnect signing when execution is disabled; it is enabled after live acceptance.
- **The browser signs; the server never does.** Approval is exact and the swap transaction is built server-side, decoded/verified, simulated, and submitted as a hash; tracking/accounting remain server-side.

- **Signing lock recovery.** `POST /signing` requires `READY` and moves it to `AWAITING_SIGNATURE`; `BUILT` orders must pass `ready` first, and `ready` must not clear the signing lock. `/signing/cancel` releases it and works even when `SWAP_ENABLED`/kill switch blocks new execution. Approval tracking marks stale/failed approvals `FAILED` after the drop timeout so an approval can be rebuilt.

- **Phase 8 accepted (2026-11-05).** Live small BSC swap completed: 1000 POP → ~0.11167 USDC, order `eca733c7…` CONFIRMED with 32+ confirmations, accounting transaction `989e9b2f…` (`tradeGroup=none` for cash-equivalent USDC). The first accounting attempt failed `NEGATIVE_BALANCE`/`NO_FUNDED_ACCOUNT`; adding BNB to the POP ledger account let the tracker auto-select the funded account and create accounting. Execution is enabled; kill switch and `SWAP_EXECUTION_ENABLED` are rollback controls.
- **Approval hash recording is allowed while execution is disabled.** Approval alone cannot move funds; the wallet approves only the exact router/amount, and the swap still requires a separate signature. The UI hides approval signing with the execution flag, but an already-signed approval hash may be recorded.
- **Signed-hash recovery is allowed while execution is disabled.** `POST /swap/orders/:id/submitted` records a hash for an already-signed `BUILT`/`READY`/`AWAITING_SIGNATURE`/built `EXPIRED` order even during a kill switch/execution disable; tracking verifies it and no new execution is authorized.
- **Gas cap.** `SWAP_MAX_GAS_USD` (default 5) is enforced at quote/build/ready; above it the operation fails closed.
- **Light theme accepted.** ADR 0011 supersedes the former dark-theme rule; the owner requested a light UI for eye comfort. Rule 13/mega-prompt/UX spec now say light theme.
- **Tracker deployment constraint (superseded by the Phase 9.x advisory lock).** The API hosts `SwapTrackingService`; a Postgres advisory lock serializes ticks across replicas. Multiple API replicas are safe, but only the lock holder processes a tick. Do not roll back to a pre-Phase-9 image with active/unaccounted orders.

- **Phase 8.x tracking hardening.** `ready` re-decodes stored calldata, re-checks the current selector/router/recipient/token/amount/minOut/executor allowlists, and uses the persisted `built_amount_out` as the minOut upper bound. Build/ready enforce a native gas preflight (`gasEstimate × eth_gasPrice`, BNB/ETH). Signing requires `READY`; the UI routes `BUILT` through “Проверить готовность”. Missing original hashes trigger same-nonce or sender/router/calldata/value searches over `SWAP_REPLACEMENT_LOOKBACK_BLOCKS` (default 240); the nonce-less content search is bounded to blocks at/after submission (2-minute grace). Unique matches are adopted and tracked; a mismatched candidate stays active (`SWAP_REPLACEMENT_PENDING`) until it reaches `SWAP_CONFIRMATIONS`, then becomes `REPLACED`; “not found”/ambiguous results stay active with an anomaly. Terminal status writes are guarded by the expected tx hash.
- **Post-accounting reorg policy.** `SWAP_CONFIRMATIONS` (default 15) is treated as final for accounting. The tracker does not automatically reverse an accounted swap; a deeper reorg requires disabling execution and an append-only manual compensating transaction. Automated compensation is a Phase 9 prerequisite.
- **Phase 8.x accepted (2026-11-05).** Final independent review: PASS. Merged as `232cab4` (PR #28); Railway API/worker deployments `SUCCESS`; `/health` and `/ready` 200; migration `0013` (`built_amount_out`) is additive. Residuals: manual attach-hash recovery outside the lookback, mocked WalletConnect UI tests, malformed-gas anomaly, approval gas not included, RPC lookback cost, accepted 2-minute content-search grace, automated post-accounting reorg compensation (Phase 9 prerequisite).

## Phase 9 — Ethereum

- **Ethereum chain config.** Chain slug `ethereum`, chainId 1; verified tokens USDC (6 decimals), LINK, BASED, APR, and native ETH. The chains table already contained Ethereum, so no schema migration is required.
- **Per-chain RPC and confirmations.** `BSC_RPC_URL` remains BSC; `ETHEREUM_RPC_URL` is used for Ethereum reads/simulation/tracking. BSC confirmations stay at `SWAP_CONFIRMATIONS` (or `SWAP_BSC_CONFIRMATIONS`), Ethereum defaults to `SWAP_ETHEREUM_CONFIRMATIONS=12`.
- **Ethereum execution is opt-in.** `SWAP_EXECUTION_ENABLED` remains the global master, but Ethereum signing additionally requires `SWAP_ETHEREUM_EXECUTION_ENABLED=true` (default false). BSC keeps its existing behavior. The kill switch remains global.
- **Router/executor.** The deterministic Kyber router/executor addresses are the same on Ethereum. Per-chain allowlists (`SWAP_BSC_*`/`SWAP_ETHEREUM_*`) are preferred; the legacy global lists remain BSC-only and are never inherited by Ethereum. Empty lists fall back to chain-specific defaults. The EVM RPC validates and caches `eth_chainId` before use.
- **Private RPC/MEV boundary.** The server uses a private/MEV-preferred Ethereum RPC for reads and simulation. WalletConnect/Tangem broadcasts the signed transaction through the wallet, so MEV protection of the broadcast is wallet-dependent; the server never signs or rebroadcasts.
- **Gas asset.** The tracker derives the native gas asset from the chain registry (BNB/ETH) and records it in the ledger with the native decimals.
- **Chain-aware UI.** `/swap` selects BSC or Ethereum, switches WalletConnect to the selected chain, binds signing to the order's chain, and shows per-chain RPC/execution status.
- **Rollback.** While any Ethereum order exists, rollback must stay on a Phase 9 image or use flags/kill switch; a pre-Phase-9 image cannot track or serve Ethereum orders.
- **Phase 9 code deployed (2026-11-05).** PR #30 merged as `c869a12`; Railway API/worker deployments `SUCCESS`; `/health` and `/ready` 200; no migration required. Ethereum execution remains disabled (`SWAP_ETHEREUM_EXECUTION_ENABLED=false`) until `ETHEREUM_RPC_URL` is configured and a live Tangem acceptance is approved.
- **Phase 9 accepted (2026-11-05).** Live Ethereum swap completed: 0.0001 ETH → 0.22526 USDC, order `92e1bada…`, tx `0x7ecdd673…`, 12 confirmations, status `CONFIRMED`. The first accounting attempt failed `SWAP_ACCOUNTING_NO_FUNDED_ACCOUNT`; adding the ETH opening balance to the Tangem Ethereum ledger account let the tracker create accounting. Ethereum execution is enabled in production; `SWAP_ETHEREUM_EXECUTION_ENABLED` and the global kill switch are rollback controls.

- **Phase 9.x tracker leader lock.** `SwapTrackingService.tick()` takes a session-level Postgres advisory lock (`pg_try_advisory_lock`) on a dedicated pool connection and releases it in `finally`; if unlock fails, the connection is destroyed. Replicas that do not acquire the lock skip the tick. This removes the single-API-replica requirement without a schema change.

## Phase 10 — On-chain reconciliation

- **Seeded assets are contract-address complete.** Migration `0015` backfills verified contract addresses/decimals for seeded BSC/Ethereum assets, and `ensureForSwapToken` repairs an existing null-contract non-native asset. A non-zero ledger asset without a contract is reported as `UNSUPPORTED` (the run completes) rather than being silently matched; imported assets may need mapping.
- **Watch-only addresses.** `watched_addresses` stores `(user, chain, address, label, enabled, last_indexed_block)`; addresses are added explicitly and auto-seeded idempotently from swap-order wallet addresses. No signing material is stored.
- **Indexer.** ERC-20 `Transfer` logs and non-zero native transfers are indexed into `indexed_transfers` by `event_key`; the API-hosted indexer uses a Postgres advisory lock, a bounded block range per tick, and a resumable per-address cursor.
- **Reconciliation is a report, not a correction.** Runs compare aggregate ledger wallet balances with the sum of on-chain balances across watched addresses and persist `MATCH`/`MISMATCH`/`MISSING_ONCHAIN`/`MISSING_LEDGER` items. Mismatches are investigated and corrected only with new append-only ledger transactions.
- **Gas backfill is raw-only.** Missing `network_fee_wei` on confirmed swap orders is filled from the receipt with audit; USD gas and accounting rows are not invented or rewritten.
- **Rollout.** `RECONCILIATION_ENABLED` defaults to false; enabling it starts the indexer. No UI in Phase 10; API/runbook only. Migrations `0014`/`0015` are additive.
