## H1. Holdout считается без warmup — подтверждена как дефект, не как причина 0

- **Статус:** подтверждена (методологический дефект), но **не как причина 0 рекомендаций**.
- **Доказательство:**
  - `apps/api/src/modules/ai-trading/ai-search.service.ts:659`: `runBacktest(definition, candidate.variant.params, folds.holdout, { initialCapitalUsd, feeBps, slippageBps, changeLookbackCandles })` — `warmupCandles` отсутствует; для фолдов он передаётся (`ai-search.evaluate.ts:45`).
  - `ai-search.helpers.ts:140`: `holdout: use.slice(searchEnd, total)` — только последние 30 дней (720 свечей для 1h) без предшествующей истории; фолды получают `warmupCandles = max(15*perDay, 240) = 360` (`:131`).
  - `backtest.engine.ts:157-164` при `warmupCandles: 0` не прогревает `samples`, scoring идёт с первой свечи holdout: первые N свечей (N = окно SMA/канала до 240) индикаторы возвращают `null` → `hold('недостаточно истории')` (`strategies/index.ts:74,135,188,249,303,415,631,695,764,839`).
  - Верифицированная аблация (stressed-фикстура 12345, 500 вариантов, 30 прошли OOS, holdout buy&hold −29.60%, префикс 360 свечей **строго до** holdout — look-ahead исключён по построению): в top-10 четыре кандидата с holdout «0 сделок / 0.00%» без warmup получили с warmup по 2 сделки — `momentum_breakout` ×3 → **−0.43% / −0.78% / −1.00% / −2.46%**, `trend_pullback` → **−1.90%**; `grid_range` (anchorLookback=219) — 12 сделок / −17.92% → **22 сделки** / −24.86%. Warmup материально меняет holdout, но в медвежьем holdout **не переворачивает знак**: 0 положительных на top-10/25/50/100 в обоих режимах; `signChanges=0`, `zeroToPositive=0` по top-100. В neutral-фикстуре top-10 `warm == now` побитово (окна стратегий короче времени до первого входа внутри 720-свечного holdout).
- **Влияние:** искажает финальный подтверждающий фильтр (кандидат с 0 сделками получает 0.00% ≤ 0 и отбрасывается как «negative holdout», `service.ts:668,670`) и делает holdout-метрику несопоставимой с OOS-метрикой. В прогоне LINK near-miss имели сделки и реальный минус (−18.82/−11.64/−6.77 по плану) — то есть не является главной причиной 0 рекомендаций.
- **Severity:** Important.
- **Минимальное исправление:** в `buildSearchFolds` возвращать holdout с warmup-префиксом (те же 360 свечей для 1h) и передавать `warmupCandles` в `runBacktest` на `service.ts:659` симметрично `evaluate.ts:45`. Тест: фикстура 1h с `slowPeriod=240`, `warmupCandles > 0` доходит до движка и holdout даёт сделки; параметризация 1h/4h/1d.
- **Риск исправления:** изменятся абсолютные holdout-returns и список рекомендаций (перебазировка артефактов); эффект двунаправленный (может добавлять убыточные входы в медвежьем holdout) — **не компенсировать** ослаблением порогов.

## H2. Holdout только для top-10 по OOS — подтверждена как факт, не подтверждена как причина 0

- **Статус:** подтверждена как ограничение дизайна; не причина 0.
- **Доказательство:**
  - `ai-search.service.ts:653-654`: сортировка по `policyScore`, `metrics.slice(0, 10)`; holdout только для этих десяти (`:655-707`).
  - Аблация: stressed-фикстура — top-10/25/50/100 дают **0/0/0/0** положительных holdout (вариантов №11–50 с устойчиво положительным holdout не существует: медвежий рынок бьёт всех). Neutral-фикстура — 9 из top-10 имеют положительный holdout: политика работает, когда рынок в holdout не падает.
- **Влияние:** сужает чувствительность, но защищает от множественного тестирования (см. H10). Расширение top-N без коррекции — manufacture ложноположительных.
- **Severity:** Minor (ограничение дизайна).
- **Минимальное исправление:** не менять выборку; добавить в `stats` счётчик «прошли OOS, но не вошли в holdout-top-10» (`metrics.length - top.length`) для наблюдаемости. Тест на новые поля `AiSearchStats` (опционально).
- **Риск исправления:** нет (если не расширять top-N).

## H3. Фильтры и их порядок — механика подтверждена; причина 0 не доказана (нет данных LINK)

- **Статус:** подтверждена механика; недостаточно данных для вывода о причине 0.
- **Доказательство:**
  - Константы `service.ts:81-84`; порядок отсева `:581-604`: сделки → медиана OOS > 0 → `positiveFolds ≥ 5` → DD ≤ 20 → худший фолд ≥ −15. `trades` — сумма по всем 8 фолдам (`helpers.ts:158`), каждая нога считается (`engine.ts:103,141`), каждый фолд принудительно закрывает позицию (`engine.ts:271-276`). MIN_TRADES=8 ⇒ в среднем ≥1 вход в ≥4 из 8 фолдов.
  - Распределение на stressed-фикстуре (500 вариантов): «too few trades» **408/500 (81.6%)** — того же порядка, что 2894/5000 (57.9%) в LINK. Медиана сделок за 8 фолдов: `momentum_breakout` 20.5, `bollinger_reversion` 11.0, `crash_protected_grid` 9.6, `donchian_breakout` 6.1, `grid_range` 5.2, `failed_breakout` 3.0, `squeeze_breakout` 2.4, `trailing_stop` 2.0, `trend_pullback` 1.7, `mean_reversion` 0.7, `dca_dip` 0.6. У 8 из 11 стратегий медианный случайный вариант входит реже одного раза за 10-дневное OOS-окно → массовый отсев «мало сделок» — структурное следствие «широкий случайный диапазон параметров × короткие окна», а не ошибка подсчёта.
- **Влияние:** доминирующий канал отсева; сам по себе 0 не объясняет и ошибкой не доказан. Для LINK нужен per-variant dump (в артефакте только `stats/candidates/nearMisses/rejectionReasons` — план, раздел 6).
- **Severity:** Minor (observability).
- **Минимальное исправление:** писать в `ai_artifacts.payload` per-variant dump (`strategyKey, params, trades, oosMedianReturnPct, positiveFolds, maxDrawdownPct, policyScore, holdoutReturnPct`). **Не трогать MIN_TRADES.**
- **Риск исправления:** рост размера артефакта; семантика метрик не меняется.

## H4. Stateful-стратегии и warmup — подтверждена (холодное состояние), измеренный эффект мал

- **Статус:** подтверждена.
- **Доказательство:**
  - `backtest.engine.ts:157-164`: warmup-свечи только добавляются в `samples`, `definition.evaluate` на них **не вызывается**; `strategyState = {}` (`:67`), первый вызов — на первой OOS-свече (`:240`). Касается и OOS-фолдов, не только holdout.
  - Аблация `stateWarm` (fold 3, 1h, дефолт + 3 случайных варианта): `trailing_stop` 3.47%/4t/DD3.50 → 3.47%/4t/3.50 (без изменений); `crash_protected_grid` 0.76%/6t/0.47 → 0.76%/6t/0.47 (без изменений); `failed_breakout` 0/0 → 0/0. В этой фикстуре эффект нулевой.
- **Влияние:** реальный дефект архитектуры (state на начало OOS не отражает 15-дневную предысторию), но в фикстурах вклад в результаты нулевой; величина зависит от того, насколько режим стратегии (HWM/mode/breakdownLevel) определяется движением именно в warmup-окне. Усиливает H1 на holdout (там state холодный в обоих режимах — `runBacktest` вообще не умеет прогревать state).
- **Severity:** Important (архитектура), с оговоркой о малом измеренном эффекте.
- **Минимальное исправление:** в `backtest.engine.ts` прогонять `definition.evaluate` по warmup-свечам **без записи сделок** и инициализировать `strategyState` из последнего `nextState`. Тест: на первой OOS-свече `ctx.state` непустой для `trailing_stop`/`crash_protected_grid`/`failed_breakout`, число сделок и точек эквити за время прогрева = 0.
- **Риск исправления:** изменятся OOS/holdout stateful-стратегий (перебазировка); нельзя допустить исполнение сигналов в период прогрева.

## H5. Look-ahead: решение и исполнение на одном close — подтверждена как смещение; не объясняет OOS+/holdout−

- **Статус:** подтверждена как систематическое смещение; не причина 0.
- **Доказательство:**
  - `backtest.engine.ts:177-180` добавляет `closeUsd` текущей свечи в `history` до решения; `:240-257` передаёт `priceUsd: candle.closeUsd`; `:262`/`:264` исполняют по тому же `close`. Защитные выходы (`:186-237`) используют open/high/low — корректно.
  - Независимая аблация (26 свечей, гэпы на open): same-close **130.44%** / DD 9.40 / PF 10.92 → next-open **120.78%** / DD 10.24 / PF 9.62 (−9.66 п.п.) → next-close **62.12%** / DD 20.28 / PF 8.73 (−68.32 п.п., DD пересекает порог 20). На 1h-фикстуре (open[i+1] ≈ close[i]) fold 0, дефолтные параметры: |Δ| ≤ 0.32 п.п., направление смешанное.
  - Вывод: смещение всегда **завышает** и OOS, и holdout; при непрерывной 1h-торговле эффект мал, при гэпах — значителен. Удаление look-ahead не может превратить отрицательный holdout в положительный.
- **Влияние:** не объясняет 0 рекомендаций; снижает доверие к абсолютным уровням метрик и может ложно пропускать варианты через DD-порог 20.
- **Severity:** Important (систематическое смещение), не Critical для данного инцидента.
- **Минимальное исправление:** исполнение по `open[i+1]` (или `close[i+1]`); блок защитных выходов `:186-237` не трогать. Тест-фикстура: на свече решения сделки нет, цена исполнения = `open[i+1] × (1 ± slippage)`; golden-тест H7 с теми же числами.
- **Риск исправления:** широкий радиус — все бэктесты, 5000×8 фолдов, holdout, LAB/PDF, parity worker-тесты; перебазировка всех сохранённых артефактов. **Не компенсировать порогами.**

## H9. Агрегация и статистика — механика подтверждена; найдены Minor-несоответствия

- **Статус:** подтверждена механика; Minor-несоответствия имён/знаменателей.
- **Доказательство:**
  - Медиана для 8 фолдов корректна (`helpers.ts:144-151`; проверено: `[1,2,3,4,−1,−2,−3,−4]` → `0.00`).
  - `maxDrawdown = Math.max(...drawdowns)` (`:161`) — худший DD **одного** фолда при капитале $1000, сбрасываемом каждый фолд (`evaluate.ts:41`); это не DD единой капитальной кривой — название агрегата неоднозначно.

- **Severity:** Minor.
- **Минимальное исправление:** документировать/переименовать дублирующие поля; выводить знаменатель `buildStats` из фактического числа фолдов. Тест: совпадение `stabilityPct` helper/сервиса для 6/8/10 фолдов.
- **Риск исправления:** переименование ключей сломает фронтенд/артефакты — нужны алиасы.

## H10. Верхнеуровневая политика «0 рекомендаций» — подтверждена как статистически разумная; 0 — правдоподобный честный исход

- **Статус:** подтверждена как статистически обоснованная.
- **Доказательство/рассуждение:**
  - Holdout (дни 150–180, `helpers.ts:140`) не участвует в отборе (`service.ts:653-654` сортирует по OOS до holdout); top-10 ограничивает множественное тестирование: сравнений на holdout 10 вместо 5000 (расширение до top-50 при независимых тестах подняло бы ожидаемые ложноположительные ~5 → ~25; в медвежьем holdout ~0).
  - Один 30-дневный holdout с low-power и long-only стратегиями доминируется направлением рынка: в медвежьем holdout `P(holdout > 0) ≈ 0` для всех кандидатов. Stressed-фикстура воспроизвела это точно: **30/500 прошли OOS-фильтры, 0/30 положительных holdout в любом режиме (top-10/25/50/100, с warmup и без)** при buy&hold holdout −29.60%. Neutral-фикстура — 9 из top-10 с положительным holdout: политика генерирует рекомендации, когда рынок не падает.
  - Near-miss из плана (+6.82%/−18.82%, +5.71%/−11.64%, +4.12%/−6.77%) — каноническая подпись честного out-of-sample провала при смене режима, а не бага: OOS-селекция словила переобучение, holdout это вскрыл. Ровно для этого holdout и существует.
  - «Сколько рекомендаций при holdout 60/90 дней» — недостаточно данных (нет свечей); расширение окна меняет судейство, а не «производит» рекомендации.
- **Влияние:** ни один из механизмов H10 не создаёт 0; политика намеренно консервативна (смещена к ложноотрицательным — план, раздел 8, это признаёт).
- **Severity:** Minor (ограничение дизайна).
- **Минимальное исправление:** для корректности не требуется. Для мощности — несколько независимых holdout-окон с коррекцией (изменение политики, вне объёма аудита).
- **Риск исправления:** N/A.

# Итоговый вердикт

## 1. Есть ли баг, объясняющий 0 рекомендаций?

**Нет бага, который «обнулил» бы честный результат; но есть реальные методологические дефекты, которые нужно чинить до следующего прогона.**

- Арифметика движка (H7), генерация вариантов (H8), агрегация (H9) — исправны или имеют только косметические дефекты. Look-ahead (H5) завышает и OOS, и holdout одновременно и не объясняет расхождение.
- **H1 подтверждён как дефект**: holdout считается без warmup (`service.ts:659`, `helpers.ts:140`), в отличие от фолдов; аблация показывает материальные изменения (0→2 сделки, 12→22 сделки), в том числе «0 сделок / 0.00% → отказ по negative holdout» для стратегий с длинными окнами. Но в медвежьем holdout warmup не переворачивает знак: 0 положительных в обоих режимах на всех top-N. H4 (холодное состояние) подтверждён кодом, измеренный эффект в фикстурах нулевой.
- **Доминирующее объяснение 0 рекомендаций — честное**: последние 30 дней LINK падали (near-miss с сильными отрицательными holdout при положительных OOS — типовой провал out-of-sample при смене режима; stressed-фикстура воспроизвела тот же паттерн 30/500 → 0/30). Текущая политика намеренно консервативна и в падающем рынке обязана давать 0. H6 (gaps/mixed quality) остаётся неизмеренным риском искажения окон.

**Вывод: 0 рекомендаций = преимущественно честный результат рынка + методологии; H1/H4/H6 — реальные дефекты доверия к метрикам, которые следует исправить и перепроверить на реальных свечах LINK.**

## 2. Какие 3 изменения дадут максимальный эффект без подгонки?

1. **H1 — симметричный warmup для holdout:** warmup-префикс в `buildSearchFolds` + `warmupCandles` в `runBacktest` (`service.ts:659`), как у фолдов. Устраняет «0 сделок → ложно-отрицательный holdout» и делает судейство одинаковым для OOS и holdout. Это повышает честность, а не число рекомендаций.
2. **H4 — прогрев состояния stateful-стратегий:** вызов `evaluate` на warmup-свечах без записи сделок в `backtest.engine.ts:157-164` с инициализацией `strategyState` из `nextState`. Устраняет артефакт холодного HWM/режима на границе OOS/holdout.
3. **Наблюдаемость данных (H6/H3/H9):** per-variant metrics dump в `ai_artifacts.payload`, метрики gaps/expected-vs-actual и границы `ok`/`synthetic` в coverage, счётчик «прошли OOS, но не вошли в top-10», корректные подписи отказов (`holdoutPassed` vs `negative holdout`), единый знаменатель `stabilityPct`. Без этого следующий прогон LINK снова будет недиагностируемым.

**Не делать:** снижение `MIN_TRADES`, ослабление DD/holdout-порогов, расширение top-N — это manufacture ложноположительных. H5 (исполнение на следующей свече) — отдельная перебазировка, не средство «получить» рекомендации.

## 3. Какие тесты/фикстуры добавить до следующего прогона?

1. **Holdout-warmup parity:** тест, что holdout-прогон получает `warmupCandles > 0` и что вариант с `slowPeriod=240` даёт сделки в holdout; параметризация 1h/4h/1d.
2. **State-warm:** тест, что на первой OOS-свече `ctx.state` непустой для `trailing_stop`/`crash_protected_grid`/`failed_breakout` и что за время прогрева нет сделок/точек эквити.
3. **Engine golden-тест (H7):** 26-свечная фикстура с точными значениями fee/slippage/amount/costBasis/PF/WR/DD/принудительного закрытия, сверенными с Python `Decimal` (числа есть в этом отчёте; эталон уже написан).
4. **Data-quality фикстура:** 1h 4320 свечей с пропуском и частью `synthetic` — coverage обязан показать не-`ok`/gap-флаг, границы фолдов строятся по `openTime`.
5. **Регрессия дат:** движок принимает полный ISO в `candle.date` без Invalid Date (`capturedAt`/`now`), плюс тест `stabilityPct`-знаменателя для 6/8/10 фолдов и per-variant dump в артефакте.
