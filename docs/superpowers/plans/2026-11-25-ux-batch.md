# UX Batch — Settings, Viber Notifications, Equity History and Finance Form

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the owner-approved UX batch: full settings sections, trade-close notifications with Viber delivery, 12-month chart+table, notes pin/attach fixes, crypto equity chart with hourly/daily/monthly ranges, compact dashboard cards, and a unified finance operation form.

**Architecture:** Additive schema (`viber_notifications`, `portfolio_equity_points`, Viber settings columns), API services for outbox/delivery and equity series, a small external `Nexter.Bot` polling client, and web components that consume the new contracts. Existing trading, sandbox and ledger rules are unchanged.

**Tech Stack:** TypeScript/NestJS/Fastify/Drizzle/PostgreSQL/Zod (API), React 19/TanStack Query/TanStack Router/Tailwind (web), Python 3/Flask/APScheduler/requests (`Nexter.Bot`), Vitest/pytest.

**Spec:** `docs/superpowers/specs/2026-11-25-ux-batch-design.md`

**Status (2026-11-25):** implementation complete on `ux-batch`; local `format:check`, lint,
typecheck, web tests, API tests (DB-backed e2e skipped without `NEXTER_TEST_DB`) and build are
green. Production migration `0054` and the `Nexter.Bot` deploy remain gated by backup/restore and
explicit owner approval (Task 11).

## Global Constraints

- Paper-only: no real money, wallets, keys, signing, swaps or exchange execution.
- Do not stop, start or edit the five Stage 3 sandbox runs.
- Money is decimal strings / PostgreSQL `numeric`; never JS float arithmetic for money.
- Every mutation is audited; no DELETE grants; append-only event/ledger rules remain.
- API errors are Russian on the web; identifiers and code comments are English.
- Zod for input validation; no `any` in the web API layer.
- New production schema changes require encrypted backup, restore check and a documented rollback.
- No secrets in code, logs, docs or screenshots.
- Existing `GET /dashboard/equity-curve` behavior and tests must keep passing.
- UI copy is Russian; base accounting currency stays USD and tax method FIFO.

## Review Focus

- A manual full close must create exactly one in-app notification and one Viber row with the realized P&L of that close, not the whole group's lifetime P&L; an idempotent replay must not duplicate it. Test: `viber-notifications.e2e.spec.ts` manual-close assertion.
- A partial manual sell must not create a “trade closed” notification. Test: `viber-notifications.e2e.spec.ts` partial-sell assertion.
- Viber pending/ack endpoints must reject missing/wrong bearer tokens and expose only `pending` rows for the owner. Test: `viber-notifications.e2e.spec.ts`.
- Hourly equity must never invent points before collection; with one point the chart shows a collection note, not a fabricated curve. Test: `equity-series.e2e.spec.ts` and `portfolio-equity-chart.test.tsx`.
- Pinned notes must stay above newer unpinned notes under both sort modes. Test: `notes-sort.test.ts`.
